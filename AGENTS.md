# Agent rules

- Booking CSV uploads use `src/lib/bookingCsv.ts` with Papa Parse logical records and strict column alignment; never split physical lines. Why: quoted multiline fields must not create phantom participants or shift payments/consent columns.
- Known invalid persisted CSV previews are blocked at the database commit transition without changing their evidence rows. Why: correcting the upload parser cannot make an already-staged corrupt plan safe.

- Booking connection displays share `latestCsvImportQuery` and `CsvImportTime` for committed manual import history; legacy sync logs are historical only. Why: one consistent query prevents stale sync activity being presented as current CSV imports.

- All booking writes from outside sources (manual CSV import, automatic sync, `booking-intake` pushes) go through `supabase/functions/_shared/booking-engine.ts`, with matching rules in `_shared/booking-logic.ts` (tests in `src/test/bookingImportLogic.test.ts`). Why: one tested place decides identity and protects staff edits.
- Participant identity is source participant ID, else name + DOB + guardian contact, scoped to an explicit source camp ID linked to one app camp; never row position or "Sr. No". Uncertain matches go to the review queue, never to a silent create. Why: CSVs have no stable IDs and get reordered.
- An import only overwrites a field when it still equals the value the previous import wrote (`synced_bookings.source_values`); rows without stored source values never get payment changes automatically. Why: staff part-payments, refunds and corrections must survive.
- Manual CSV previews use service-only server snapshot/staging RPCs and immutable persisted plans; commits use the authenticated admin-only `commit_csv_safety_run` transaction, table-lock serialization, unchanged global evidence and complete `booking_import_changes` audit. Why: stale/parallel attempts must abort without partial writes and committed run retries must not duplicate.
- Evidence freshness is checked by a server-computed digest (`csv_safety_evidence` / `csv_safety_snapshot_digest`), never by sending the full snapshot back; runs without a stored digest are stale. Backend errors go through `_shared/booking-errors.ts` and the client `importPreviewContract`, which fail closed. Why: the multi-MB round trip hit the 8s statement timeout and raw error objects rendered as "[object Object]".
- Person proof requires name, DOB and normalized guardian email OR phone across all profiles and registrations; the snapshot aggregate has no Data API row cap, and explicit holds remain held. Why: cross-camp attendance is legitimate but conflicting or multiple person evidence must not silently merge.
- Automatic import and legacy force-resolve paths remain disabled; safety review supports persisted skips only. Why: manual imports require explicit confirmation and disputed identity/medical/consent evidence needs separate verified review.
- Family counts inferred from parent contact are estimates; only source booking IDs give verified booking counts. Why: shared contact details don't prove a shared booking.
- Source "Total Amount" is per child after sibling discount: owed = total − paid (never subtract the discount). Refund and cancellation semantics are unproven, so those rows are undetermined (null owed, review) — never treat a refund as a payment or discount. Bulk data repairs record before/after in `data_repair_audit` (staged|applied|held). Why: verified on real exports; no refund/cancel evidence yet.
- Rolling back a `data_repair_audit` batch must re-read every target row first: revert only rows whose current values still equal the batch's `after` state; skip and report rows staff changed since, and never delete inserted registrations blindly — check for dependent rows (attendance, run rows, player links) created after the batch and hold those for review. Why: staff edits made after a repair must survive a rollback.
- Sync & Review shows saved CSV previews read-only via `src/lib/savedPreviews.ts`: latest per source_system+source_camp_id, older kept as history, all pages loaded, load errors shown as unknown; a digest means "recheck before import", never verified. Why: pending review queue and committed history exclude previews, which hid saved exceptions.
